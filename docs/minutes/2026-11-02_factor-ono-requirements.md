# 学習支援アプリ企画書

## 1. 背景
大学の授業では、専門用語や抽象的な概念、数式などを学ぶ機会が多い。しかし、授業で学んだ内容が日常生活や自分の興味とどのように関係しているのか分からず、知識の意味や具体的な活用方法を理解しにくい場合がある。

例えば、ネットワークの授業でパケット通信について学んでも、それが実際にどのような場面で使われているのか分からなければ、内容に興味を持つきっかけが生まれにくい。一方で、オンラインゲームでの通信に使われていると知れば、身近な興味をきっかけに、さらに調べてみたいと思う可能性がある。

また、数学などで数式の計算方法を学んでも、その概念が何を表しているのか、どのような場面で使われているのかを理解できないと、公式を暗記するだけになってしまうことがある。

こうした経験から、授業で学んだ知識を自分の興味や身近な事柄と結びつけ、知識の意味や活用方法を理解できる仕組みが必要だと考えた。

## 2. 課題
新しく出てくる概念・考えに対して日常生活や自分の興味関心と関係なさすぎて理解できない。関係を見出せない（から興味ない）（ネットワークのパケットの話、OSのスケジューリングの話）
- 授業で学んだ抽象的な概念を、具体的なイメージとして理解しにくい。
- 学んだ知識が日常生活や自分の興味とどう関係しているのか分かりにくい。
- 知識の使われ方が分からず、自分から調べたり、学習を深めたりするきっかけが少ない。
- 既に知っていることと新しく学んだことのつながりを、自分で発見することが難しい。
- 学んだ知識を、授業とは異なる場面で活用することが難しい。

現時点では、これらは企画者自身の経験をもとにした仮説である。他の大学生にも同じ課題があるのか、今後の調査で確認する必要がある。

## 3. 目的・方針

### 目的
身近なことに目を向けて学習をもっと楽しくさせる。

授業で学んだ知識を自分の興味や日常生活と結びつけて理解し、知識同士のつながりを発見することで、学んだ知識を別の場面でも活用できるようにする。（流動性知能への接続）

また、知識と身近な事柄との関係を知ることで、学習内容への興味や、自分から調べてみようとする意欲を高めることを目指す。（学習へのモチベを増やす）

### 方針（開発の進め方・提供方法・使用技術）
- アジャイル（スクラム×カンバン）
- アプリ提供方法（FlutterWeb）
- 使用技術：デザイン Figma／フロント TypeScript／バックエンド のちに決める（Python・Go・Rust・Rubyのいずれか）
- 身近な具体例から理解する：抽象的な概念を説明する前に、利用者の興味に関連した具体例を提示する。
- 知識のつながりを発見する：授業で学んだ内容と、利用者の興味や既に知っている知識との関係を提示する。
- つながりの理由を説明する：単に関連する情報を並べるのではなく、共通点や関係する仕組みを説明する。
- 利用者自身が考える：AIの提案をそのまま受け入れるのではなく、利用者が内容を確認し、自分で納得したつながりを整理する。
- 最終的には自立した学習を目指す：AIに頼り続けるのではなく、利用者自身が知識のつながりを見つけ、新しい場面で活用できるようにする。

## 4. システム概要
1. 趣味関心をまず登録
2. 授業資料をインポート
3. 趣味関心と授業資料を紐づける
   - 例：確率とガチャの話／ネットワークパケットとオンラインゲーム（ラグとかその辺の話）／オペレーティングシステムとやることリスト（優先度順とか、マイペース＝ラウンドロビンとか）

本システムは、授業で学んだ知識と利用者の興味・関心をAIによって結びつけ、学習内容の理解や知識の活用を支援するアプリである。

利用者は授業資料を登録し、AIが資料から重要な用語や概念を抽出する。さらに、利用者が事前に登録した趣味や興味に関連する具体例を提示することで、授業内容を身近なものとして理解できるようにする。

その後、授業で学んだ知識と既に知っている知識とのつながりをAIが提案する。利用者は提案された内容と説明を確認し、納得したものを知識マップに追加する。

知識マップでは、知識を点、知識同士のつながりを線として表示する。つながりには、自分の考えや疑問なども記録できる。

このように、具体例による理解、知識のつながりの発見、知識の整理、別の場面での活用という流れを支援する。

## 5. 用語の定義（前回決めたからここは飛ばす）
| 用語 | 定義 |
| --- | --- |
| 授業知識 | 授業資料や講義を通して学んだ用語、概念、仕組みなど、単語単位 |
| 興味・関心 | 利用者が好きなこと、趣味、気になっている分野など |
| 具体例 | 抽象的な概念を理解しやすくするために示す、実際の利用場面や身近な事例 |
| 知識のつながり | 異なる知識の間にある共通点、関係性、応用可能性など |
| AIによる提案 | 授業知識と興味・関心、既存の知識などをもとにAIが提示する具体例や関連性 |
| 知識マップ | 知識を点、知識同士のつながりを線として視覚的に整理したもの。知識グラフ・ナレッジグラフと同義 |
| 知識の活用 | 学んだ知識を、授業とは異なる問題や場面で利用すること |

## 6. 機能

### 6.1 興味・関心の登録機能
利用者が好きなことや趣味、興味のある分野を登録する機能。初回利用時に基本的な興味・関心を登録し、その後も自由に追加・編集できるようにする。また、日常生活で新しく気になったことも、一時的なメモとして登録できるようにする。

### 6.2 授業資料の登録機能
授業で使用したPDFやスライドなどの資料を登録する機能。登録された資料をもとに、AIが授業の重要な用語や概念を抽出する。

### 6.3 重要な概念の抽出機能
AIが授業資料を分析し、学習内容の中から重要な用語や概念を抽出する機能。利用者が授業内容のどこに注目すればよいか分かるように、重要な内容を整理して提示する。

### 6.4 興味に関連した具体例の提示機能
抽出した概念について、利用者の興味・関心に関連する具体例をAIが提示する機能。例えば、パケット通信について学んだ場合、オンラインゲームでの通信との関係を具体例として提示する。概念の説明だけでなく、まず身近な例を示すことで、学習内容への興味や理解を促す。

### 6.5 知識のつながり提案機能
授業で学んだ知識と、利用者の興味・関心や既に知っている知識とのつながりをAIが提案する機能。提案する際には、次の内容を説明する。
- それぞれの知識にどのような共通点があるのか。
- なぜ、どのような仕組みでつながっているのか。
- 実際にどのような場面で関係しているのか。

根拠が不十分な場合は、無理に関連付けず、可能性のあるつながりとして区別して提示する。また、利用者が説明の根拠を確認できるよう、参考資料や情報源も提示する。

### 6.6 知識マップ機能
学んだ知識や興味・関心、それらのつながりを視覚的に整理する機能。知識を点、知識同士のつながりを線として表示する。つながりには、利用者自身の考えや疑問、発見したことなどを記録できるようにする。AIが提案したつながりは、利用者が確認するまでは確定したものとして扱わない。利用者が納得したものだけを「マップに追加」できるようにする。

### 6.7 メモ・振り返り機能
学習中に気づいたことや疑問、知識をどのように活用できそうかなどを記録する機能。利用者が自分の言葉で考えを整理し、学習内容を振り返ることを支援する。

## 7. システム化の範囲

### システム化する範囲
- 利用者の興味・関心の登録と管理
- 授業資料の登録と管理
- AIによる重要な用語・概念の抽出
- AIによる具体例の提示
- AIによる知識のつながりの提案と説明
- 知識マップの作成・編集・表示
- メモや振り返り内容の記録

### システム化しない範囲（スコープ外）
- 大学の授業資料や成績情報を大学のシステムから自動取得すること
- 授業の出席管理や課題提出の管理
- 利用者の学習成果を成績として評価すること
- AIの提案だけで知識の正しさを最終判断すること

AIは学習を支援する役割とし、知識の正しさやつながりについては、利用者が根拠を確認できる仕組みを設ける。

## 8. 導入・移行計画

### 導入計画
最初は少人数の大学生を対象に試験的に利用してもらい、操作性や学習への効果を確認する。導入時には、利用者に興味・関心を登録してもらい、授業資料を使った学習の流れを説明する。その後、実際にシステムを使用してもらい、使いやすさや提案内容の分かりやすさについて意見を集める。

### 移行計画
試験利用で得られた意見や問題点をもとに、機能や画面構成、AIの提案内容を改善する。将来的には、利用者が自分の知識や興味を継続的に蓄積し、授業ごとの学習だけでなく、長期的な知識の整理にも利用できる状態を目指す。

※対象者や利用環境、実際の導入時期については今後検討する。

## 9. 運用・保守

### 運用
利用者が授業後などに授業資料を登録し、AIの提案を確認しながら利用することを想定する。利用者は、必要に応じて興味・関心や知識マップを更新する。AIが提示する関連性は参考情報として扱い、利用者自身が確認してから知識マップに追加する。

### 保守
- AIが誤った情報や不適切な関連性を提示していないか確認する。
- AIの説明に参考情報や根拠が示されているか確認する。
- 利用者からの意見や不具合報告をもとに機能を改善する。
- 授業資料や利用者の興味・関心などのデータを適切に管理する。
- 必要に応じてAIモデルや外部サービスの変更に対応する。

また、授業資料や個人情報を扱うため、データの保存方法やアクセス権限、削除方法なども検討する必要がある。

## 10. 工程計画
| 工程 | 内容 |
| --- | --- |
| 1. 課題調査 | 大学生へのインタビューやアンケートを行い、実際にどのような学習上の課題があるか調べる |
| 2. 要件整理 | 調査結果をもとに、対象者や必要な機能を明確にする |
| 3. 試作 | 授業資料の登録、具体例の提示、知識のつながりの提案など、必要な機能を試作する |
| 4. 動作確認 | 各機能が正しく動作するか、AIの提案が適切か確認する |
| 5. 利用実験 | 実際に大学生に使用してもらい、学習への効果を調べる |
| 6. 評価・改善 | 実験結果や利用者の意見をもとに、機能やシステムを改善する |

特に最初の検証では、「利用者の興味に関連した具体例を概念説明の前に提示すると、理解や学習意欲が高まるか」を確認する。通常の概念説明を受ける場合と、興味に関連した具体例を先に見る場合を比較し、理解度や自分から調べたいと思うか、別の問題に知識を活用できるかなどを評価する。

具体的な実施時期や期間は、開発規模や研究計画に合わせて決定する。

## 11. 体制
| 担当 | 役割 |
| --- | --- |
| 企画・開発担当 | システムの企画、設計、実装、改善 |
| 指導教員 | 研究内容や開発方針への助言、実験計画の確認 |
| 利用者・実験協力者 | 試作システムの利用、アンケートやインタビューへの協力 |
| AI・外部サービス | 授業資料の分析、具体例や知識のつながりの提案 |

開発を複数人で行う場合は、画面設計、データ管理、AI連携などの担当を分けることも検討する。

## 12. 成果物
1. 課題調査資料：大学生へのアンケートやインタビューの結果をまとめた資料。
2. 要件定義書：システムの目的、対象者、必要な機能、システム化の範囲をまとめた資料。
3. 画面設計資料：アプリの画面構成や操作の流れをまとめた資料。
4. 試作システム：授業資料の登録、具体例の提示、知識のつながりの提案、知識マップなどを備えたアプリ。
5. 実験・評価資料：利用実験の方法、結果、分析をまとめた資料。
6. 最終報告書：企画から開発、実験、評価までの取り組みと成果をまとめた資料。

最終的には、授業で学んだ知識を自分の興味や既存の知識と結びつけ、さらに別の場面でも活用できるよう支援する学習アプリの試作品と、その効果を検証した結果を成果物とする。
